title: Organizations

Organizations represent the companies, teams, or accounts that your users belong to. They add a layer of structure on top of user profiles, enabling B2B segmentation, account-based messaging, and organization-level event tracking.

<Callout type="info">
**Organizations vs Users**: Users are individual people who receive messages. Organizations group users together and can have their own properties and events. A user can belong to multiple organizations.
</Callout>

---

## Organization Profiles

Every organization has a profile containing:

- **Identifiers**: How Lunogram recognizes the organization
- **Name**: A display name for the organization
- **Custom data**: Any properties you define (plan, industry, size, etc.)
- **Members**: Users who belong to the organization

### Identifiers

| Field | Description |
|-------|-------------|
| `external_id` | Your system's unique identifier for the organization (company ID, account ID, workspace ID) |

The `external_id` is required and must be unique within your project. Lunogram uses it to match organizations across API calls — if you upsert an organization with the same `external_id`, the existing record is updated rather than duplicated.

---

## Creating Organizations

Create organizations through the Admin API. If an organization with the same `external_id` already exists, the call updates it instead.

```bash
curl -X POST https://your-instance.com/api/admin/projects/{projectId}/subjects/organizations \
  -H "Authorization: Bearer sk_..." \
  -H "Content-Type: application/json" \
  -d '{
    "external_id": "acme_inc",
    "name": "Acme Inc",
    "data": {
      "plan": "enterprise",
      "industry": "technology",
      "employee_count": 250,
      "arr": 120000
    }
  }'
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `external_id` | string | Yes | Your unique identifier for this organization |
| `name` | string | No | Display name |
| `data` | object | No | Custom properties |

## Custom Data

Store any data you need on organization profiles. Custom properties let you segment users by organization attributes, personalize messages with company context, and build organization-level rules in lists.

### Setting Custom Data

Pass custom data as a JSON object when creating or updating an organization:

```bash
curl -X POST https://your-instance.com/api/admin/projects/{projectId}/subjects/organizations \
  -H "Authorization: Bearer sk_..." \
  -H "Content-Type: application/json" \
  -d '{
    "external_id": "acme_inc",
    "name": "Acme Inc",
    "data": {
      "plan": "enterprise",
      "industry": "technology",
      "region": "north_america",
      "employee_count": 250,
      "arr": 120000,
      "features": ["sso", "audit_log", "api_access"],
      "billing": {
        "cycle": "annual",
        "currency": "USD"
      }
    }
  }'
```

### Using Custom Data

Once stored, organization data is available across Lunogram:

**In lists** (segmentation):
```
organization.plan = "enterprise"
AND
organization.arr > 50000
```

**In campaigns** (personalization):
```handlebars
Hi {{ user.first_name }},

Your team at {{ organization.name }} has been using the {{ organization.plan }} plan.
```

### Common Custom Properties

| Property | Type | Use Case |
|----------|------|----------|
| `plan`, `tier` | string | Account-based segmentation |
| `industry`, `vertical` | string | Industry targeting |
| `employee_count`, `team_size` | number | Size-based segmentation |
| `arr`, `mrr` | number | Revenue-based segmentation |
| `region`, `country` | string | Geographic targeting |
| `signup_date`, `renewal_date` | date | Lifecycle targeting |
| `features` | array | Feature-based segmentation |
| `csm`, `account_owner` | string | Internal routing |

## Updating Organizations

Update an existing organization by its internal ID:

```bash
curl -X PATCH https://your-instance.com/api/admin/projects/{projectId}/subjects/organizations/{organizationId} \
  -H "Authorization: Bearer sk_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Acme Inc (Enterprise)",
    "data": {
      "plan": "enterprise",
      "arr": 150000
    }
  }'
```

The `data` field replaces the entire custom data object. To preserve existing properties, include them in the update.

## Members

Members are the users who belong to an organization. The membership link can also carry its own custom data, such as a user's role or permissions within that organization.

### Adding Members

Add a user to an organization by their user ID:

```bash
curl -X POST https://your-instance.com/api/admin/projects/{projectId}/subjects/organizations/{organizationId}/users \
  -H "Authorization: Bearer sk_..." \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "uuid-of-the-user",
    "data": {
      "role": "admin",
      "department": "engineering",
      "joined_org": "2025-01-15"
    }
  }'
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `user_id` | UUID | Yes | The internal ID of the user to add |
| `data` | object | No | Custom data specific to this membership |

If the user is already a member, the call updates their membership data instead.

### Member Data vs User Data

Member data is specific to the user's relationship with that organization. It's separate from the user's profile data.

| Data Type | Stored On | Example |
|-----------|-----------|---------|
| **User data** | User profile | `first_name`, `email`, `timezone` |
| **Organization data** | Organization profile | `plan`, `industry`, `arr` |
| **Member data** | Membership link | `role`, `department`, `permissions` |

This separation means a user can be an "admin" in one organization and a "viewer" in another, without conflicting data.

### Listing Members

Retrieve the members of an organization:

```bash
curl https://your-instance.com/api/admin/projects/{projectId}/subjects/organizations/{organizationId}/users \
  -H "Authorization: Bearer sk_..."
```

### Removing Members

Remove a user from an organization:

```bash
curl -X DELETE https://your-instance.com/api/admin/projects/{projectId}/subjects/organizations/{organizationId}/users/{userId} \
  -H "Authorization: Bearer sk_..."
```

Removing a member only removes the association — neither the user nor the organization is deleted.

## Organization Events

Organizations have their own event timeline, separate from user events. Organization events track things that happen at the company level rather than the individual level.

### System Events

Lunogram automatically emits the following system events:

| Event | When |
|-------|------|
| `organization.created` | A new organization is created |
| `organization.updated` | An organization's properties are updated |
| `organization.user.added` | A user is added to an organization |
| `organization.user.updated` | A member's membership data is updated |
| `organization.user.removed` | A user is removed from an organization |

### Viewing Events

Retrieve the event history for an organization:

```bash
curl https://your-instance.com/api/admin/projects/{projectId}/subjects/organizations/{organizationId}/events \
  -H "Authorization: Bearer sk_..."
```

### Using Organization Events

Organization events can trigger journeys and power segmentation rules, just like user events. For example:

- **Account onboarding**: When `organization.created` fires, start an onboarding journey for all members
- **Plan change follow-up**: When `organization.updated` fires and the plan changed, notify the account owner
- **Team growth**: When `organization.user.added` fires, send a welcome message to the new member

## Segmentation with Organizations

Organizations integrate deeply with Lunogram's list rules. You can build segments that combine user, organization, and member conditions.

### Organization Property Rules

Filter users based on the organizations they belong to:

```
Organization has plan = "enterprise"
```

This matches all users who are members of at least one organization where `plan` equals "enterprise".

### Member Property Rules

Filter users based on their membership data within organizations:

```
Organization has plan = "enterprise"
  Members matching role = "admin"
```

This narrows the match to only members who have the "admin" role in an enterprise organization.

### Organization Event Rules

Filter users based on events that happened to their organizations:

```
Organization did "organization.updated" at least 1 time in the last 30 days
```

This matches users who belong to organizations that were updated recently.

### Combining Conditions

Combine organization rules with user property and event rules for precise targeting:

```
user.plan = "premium"
AND
Organization has industry = "technology"
AND
Organization member has role = "admin"
```

## Using Organizations

Once created, organizations integrate with other Lunogram features:

| Feature | How Organizations Are Used |
|---------|---------------------------|
| **Lists** | Segment users by organization properties, member roles, and organization events |
| **Journeys** | Trigger journeys from organization events; add all organization members to a journey |
| **Campaigns** | Personalize messages with organization data (name, plan, custom properties) |
| **Rules** | Build rules that filter users based on their organization memberships |

## API Reference

All organization endpoints are scoped to a project:

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/admin/projects/{projectId}/subjects/organizations` | List organizations |
| `POST` | `/api/admin/projects/{projectId}/subjects/organizations` | Create or update organization |
| `GET` | `/api/admin/projects/{projectId}/subjects/organizations/{id}` | Get organization |
| `PATCH` | `/api/admin/projects/{projectId}/subjects/organizations/{id}` | Update organization |
| `DELETE` | `/api/admin/projects/{projectId}/subjects/organizations/{id}` | Delete organization |
| `GET` | `/api/admin/projects/{projectId}/subjects/organizations/{id}/users` | List members |
| `POST` | `/api/admin/projects/{projectId}/subjects/organizations/{id}/users` | Add member |
| `DELETE` | `/api/admin/projects/{projectId}/subjects/organizations/{id}/users/{userId}` | Remove member |
| `GET` | `/api/admin/projects/{projectId}/subjects/organizations/{id}/events` | List organization events |

### Query Parameters

List endpoints support pagination and search:

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `limit` | int | 20 | Maximum results to return |
| `offset` | int | 0 | Number of results to skip |
| `search` | string | — | Filter by name or external ID |
