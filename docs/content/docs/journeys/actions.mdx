Actions are modular integrations that extend what your journeys can do. Each action is a reusable configuration — such as a webhook endpoint or an external API connection — that can be called from journey steps to interact with the outside world.

## How Actions Work

Actions follow a two-step model:

1. **Create an Action** — Configure a reusable integration (e.g., set up API credentials, define an endpoint). This is done in the **Actions** tab.
2. **Use it in a Journey** — Add an **Action** step to a journey, select the action and the function to execute, and configure the input parameters.

When a user reaches an action step during a journey, the platform executes the selected function, passes the configured input, and makes the response available to subsequent steps.

## Creating an Action

Navigate to the **Actions** tab and click **Create Action**. You'll be prompted to select the type of action to create.

| Field | Description |
|-------|-------------|
| Name | A descriptive name for the action (e.g., "Stripe API", "Slack Notifications") |
| Type | The action module to use (e.g., Webhook) |
| Configuration | Module-level settings such as API keys or authentication (varies by type) |

After creating an action, you can test the configuration directly from the action detail page using the **Test** button.

## Using Actions in Journeys

Add an **Action** step to your journey and configure it:

| Parameter | Description |
|-----------|-------------|
| Name | Display name for the step |
| Data Key | Unique key to reference the result in later steps ([learn more](data)) |
| Action | The action to execute (created in the Actions tab) |
| Function | Which function to call on the action |
| Input | Parameters for the function (fields are generated from the function's input schema) |

### Accessing Action Results

Action responses are stored under the step's data key and can be referenced in subsequent steps using Handlebars:

```handlebars
{{ journey.my_action.body }}
{{ journey.my_action.endpoint }}
```

This works in campaign templates, gate conditions, user updates, and any other step that supports Handlebars expressions.

## Action Modules

Actions are powered by WASM modules. Each module defines its own configuration schema, available functions, and input/output formats.

### Webhook

The **Webhook** module sends HTTP requests to external endpoints. Use it to integrate with any API or service that accepts HTTP requests.

#### Function: Send Request

| Input | Description |
|-------|-------------|
| HTTP Method | The request method (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`) |
| Endpoint URL | The URL to send the request to |
| Headers | Optional HTTP headers (e.g., `Authorization`, `Content-Type`) |
| Request Body | Optional body content (supports JSON, XML, or plain text) |

The response metadata includes:

| Field | Description |
|-------|-------------|
| `method` | The HTTP method that was used |
| `endpoint` | The URL that was called |
| `body` | The parsed response body (JSON responses are returned as structured objects) |
| `headers` | The response headers |

#### Example: Enrich User Data via API

1. Create a **Webhook** action named "User Enrichment API".
2. In your journey, add an **Action** step with data key `enrichment`.
3. Configure the function:
   - **Method**: `POST`
   - **Endpoint**: `https://api.example.com/enrich`
   - **Headers**: `Authorization: Bearer {{user.api_token}}`
   - **Body**: `{"email": "{{user.email}}"}`
4. Add a subsequent **Update** step to save the enriched data:

```json
{
  "company": "{{ journey.enrichment.body.company }}",
  "title": "{{ journey.enrichment.body.title }}"
}
```

#### Example: Notify Slack on Purchase

1. Create a **Webhook** action named "Slack Notification".
2. Add an **Action** step after a gate that checks for high-value purchases.
3. Configure:
   - **Method**: `POST`
   - **Endpoint**: `https://hooks.slack.com/services/...`
   - **Headers**: `Content-Type: application/json`
   - **Body**: `{"text": "🎉 {{ user.name }} just made a ${{ journey.entrance.event.amount }} purchase!"}`

## Testing Actions

Actions can be tested at two levels:

- **Module test** — From the action detail page, click **Test** to validate the module-level configuration (e.g., verify API credentials are correct).
- **Function test** — From the journey editor, click **Test** on an action step to execute the function with the configured input and inspect the response.

<Callout type="info">
Test executions run in real-time against the actual endpoint. Use test or staging URLs when validating webhook actions to avoid unintended side effects.
</Callout>

## Combining Actions with Other Steps

Actions are most powerful when combined with other journey step types:

| Pattern | Description |
|---------|-------------|
| Action → Gate | Call an API, then branch based on the response |
| Action → Update | Fetch external data and save it to the user profile |
| Action → Send | Retrieve personalized content, then send it in a message |
| Gate → Action | Only call the API when certain conditions are met |
| Delay → Action | Wait for the right moment before making an API call |
