# Storage (Uploads)

Lunogram supports two storage methods for uploading assets like images for templates:

- **Local** - Store files on the local filesystem (default)
- **S3** - Store files in any S3-compatible object storage

## Configuration

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `STORAGE_TYPE` | `local` \| `s3` | `local` | Storage driver to use |
| `STORAGE_MAX_UPLOAD_SIZE` | number | `10485760` | Maximum upload size in bytes (default 10MB) |

## Local Storage

This is the default storage method. Files are stored on the local filesystem and served from your base URL.

### Configuration

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `STORAGE_LOCAL_UPLOAD_DIRECTORY` | string | `./uploads/documents` | Directory to store uploaded files |

### Example

```bash
STORAGE_TYPE=local
STORAGE_LOCAL_UPLOAD_DIRECTORY=/var/lib/lunogram/uploads
```

<Callout type="warning">
When using local storage in a clustered deployment, uploaded files will only exist on the node that received the upload. Consider using S3 storage for multi-node deployments.
</Callout>

## S3 Storage

The S3 storage method supports any S3-compatible object storage service including:

- AWS S3
- [DigitalOcean Spaces](https://docs.digitalocean.com/products/spaces/)
- [Cloudflare R2](https://developers.cloudflare.com/r2/)
- [MinIO](https://min.io/)
- [Backblaze B2](https://www.backblaze.com/b2/)

### Configuration

| Key | Type | Required | Description |
|-----|------|----------|-------------|
| `STORAGE_TYPE` | `s3` | Yes | Enable S3 storage |
| `STORAGE_S3_BUCKET` | string | Yes | The name of your bucket |
| `STORAGE_S3_REGION` | string | No | The region your bucket is in |
| `STORAGE_S3_ENDPOINT` | string | No | Custom endpoint for non-AWS services |
| `STORAGE_S3_ACCESS_KEY` | string | No | Access key (can use IAM roles instead) |
| `STORAGE_S3_SECRET_KEY` | string | No | Secret key (can use IAM roles instead) |

### AWS S3 Example

Using explicit credentials:

```bash
STORAGE_TYPE=s3
STORAGE_S3_BUCKET=my-lunogram-uploads
STORAGE_S3_REGION=us-east-1
STORAGE_S3_ACCESS_KEY=AKIAIOSFODNN7EXAMPLE
STORAGE_S3_SECRET_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
```

Using IAM roles (EKS, EC2, ECS):

```bash
STORAGE_TYPE=s3
STORAGE_S3_BUCKET=my-lunogram-uploads
STORAGE_S3_REGION=us-east-1
# No credentials needed - uses instance role
```

### DigitalOcean Spaces Example

```bash
STORAGE_TYPE=s3
STORAGE_S3_BUCKET=my-space-name
STORAGE_S3_REGION=nyc3
STORAGE_S3_ENDPOINT=https://nyc3.digitaloceanspaces.com
STORAGE_S3_ACCESS_KEY=your-spaces-access-key
STORAGE_S3_SECRET_KEY=your-spaces-secret-key
```

### Cloudflare R2 Example

```bash
STORAGE_TYPE=s3
STORAGE_S3_BUCKET=my-r2-bucket
STORAGE_S3_ENDPOINT=https://your-account-id.r2.cloudflarestorage.com
STORAGE_S3_ACCESS_KEY=your-r2-access-key
STORAGE_S3_SECRET_KEY=your-r2-secret-key
```

### MinIO Example

```bash
STORAGE_TYPE=s3
STORAGE_S3_BUCKET=lunogram
STORAGE_S3_ENDPOINT=http://minio:9000
STORAGE_S3_ACCESS_KEY=minioadmin
STORAGE_S3_SECRET_KEY=minioadmin
```

## Docker Compose Example

Using MinIO as S3-compatible storage:

```yaml
services:
  lunogram:
    image: lunogram/lunogram:latest
    environment:
      STORAGE_TYPE: s3
      STORAGE_S3_BUCKET: uploads
      STORAGE_S3_ENDPOINT: http://minio:9000
      STORAGE_S3_ACCESS_KEY: minioadmin
      STORAGE_S3_SECRET_KEY: minioadmin
    depends_on:
      - minio

  minio:
    image: minio/minio:latest
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    volumes:
      - minio-data:/data
    ports:
      - "9000:9000"
      - "9001:9001"

volumes:
  minio-data:
```

## Bucket Permissions

Ensure your S3 bucket has appropriate permissions. At minimum, Lunogram needs:

- `s3:PutObject` - Upload files
- `s3:GetObject` - Read files
- `s3:DeleteObject` - Delete files

### Example IAM Policy

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:DeleteObject"
      ],
      "Resource": "arn:aws:s3:::my-lunogram-uploads/*"
    }
  ]
}
```

## Using a CDN

For better performance, you can serve uploaded assets through a CDN:

1. Configure your CDN to pull from your S3 bucket or Lunogram instance
2. Set up appropriate cache headers
3. Use the CDN URL in your templates

<Callout type="info">
The uploaded file URLs are returned in the API response. You can configure your frontend to rewrite these URLs to your CDN domain.
</Callout>
