---
title: SMTP
description: Where SMTP fits in Lunogram — platform mail, not a project email provider
---

<Callout type="warn">
  SMTP is not available as a **project** email provider, and is not planned as
  one. It is how the platform sends its own mail. See below.
</Callout>

Lunogram has two kinds of outbound email, and SMTP serves only one of them.

## Platform mail — SMTP is supported

Account confirmation, password resets and the security notices that go with them are sent by the platform itself, and SMTP is one of the two channels it can use:

```yaml
mail:
  channel: smtp
  from:
    address: no-reply@example.com
  smtp:
    host: smtp.example.com
    port: 587
    username: lunogram
    password: "${SMTP_PASSWORD}"
    tls: starttls
```

Any SMTP-compatible service works. See [Sending mail](/docs/settings/mail) for the full reference, including the webhook channel and how to override the messages.

| Provider | Host | Port |
| -------- | --------------------- | ---- |
| Gmail | smtp.gmail.com | 587 |
| Outlook | smtp-mail.outlook.com | 587 |
| Yahoo | smtp.mail.yahoo.com | 587 |
| Fastmail | smtp.fastmail.com | 587 |

<Callout type="info">
  Most personal email providers have low daily send limits (100–500 emails/day).
  That is usually fine for platform mail, which is a handful of messages per
  admin, but it is not a campaign sender.
</Callout>

## Project mail — use a provider integration

Campaigns, journeys and broadcasts send through a project's configured provider. Those are WASM modules, and a module reaches the network through the host's HTTP function — there is no raw TCP socket in the sandbox, which is what SMTP would need. An SMTP provider module therefore cannot be built without opening sockets to every provider module, which is not a trade worth making for one protocol.

Use an HTTP provider instead — [Resend](/integrations/resend), Mailgun, SendGrid or Amazon SES — or the webhook provider, which posts each message to an endpoint of yours that can relay it however you like, SMTP included.
